Factory Inventory
ManagementSystem architecture

A demo application that reads inventory, orders, spending and backlog data for three warehouses and presents it through six filtered views. Everything is served from JSON files held in memory — there is no database, and the single write route appends to that memory rather than to disk.

Why the state lives in a module, not a store

useFilters.js declares its four refs at module scope, outside the exported function. Every importer therefore shares one instance — a singleton by module caching rather than by Pinia or Vuex. Seven files import it, and the filter bar mutates the same refs the views watch.

Layers

Two processes, started separately, talking over CORS-opened HTTP on localhost. Vite serves the client on port 3000; uvicorn serves the API on 8001. There is no dev proxy, so the API origin is hardcoded in the client.

Seams worth knowing before you change anything

Found by reading the code against the running servers and probing each route. Ordered by what would bite you first.

  1. 1

    Adding a task silently does nothing

    The client ships four task methods and two purchase-order methods against routes the API never declares. All six return 404 when probed against the running server; the backend has zero non-GET routes.

    App.vue calls api.createTask(), catches the failure, logs it to the console and returns. No error surfaces, and the new task never appears. Delete and toggle only appear to work because they short-circuit on the four hardcoded tasks in useAuth.js before reaching the network.

    client/src/api.js:77–104 · client/src/App.vue:97–105 · client/src/composables/useAuth.js:26

  2. 2

    Dashboard renders a component that does not exist

    Dashboard.vue renders <PurchaseOrderModal> with three props and two event handlers. There is no such file in client/src/components/, and it is neither imported nor registered — the imports stop at BacklogDetailModal. Vue treats an unresolved component as a no-op, so it logs a warning and renders nothing rather than failing, which is why the page looks intact. Confirmed in the browser console on a clean dashboard load.

    Everything around it was built: the state (showPOModal, selectedBacklogForPO, poModalMode) and the handlePOCreated handler all exist. Only the component and the route are missing.

    On the server side the same feature stops short. CreatePurchaseOrderRequest is defined and never referenced by a route, and purchase_orders.json holds zero records — so because /api/backlog derives has_purchase_order by matching against that empty list, the flag is always false and the branch behind it is unreachable.

    client/src/views/Dashboard.vue:289–295, 305–312, 665 · server/main.py:115 · server/main.py:172–178 · server/data/purchase_orders.json

  3. 3

    Quarter filtering exists only on the server

    QUARTER_MAP resolves Q1-2025 through Q4-2025, but the filter bar offers only the twelve months plus “all”, and no client code emits a quarter value. The capability is reachable through the API but not the UI.

    The same helper also fails open: a Q-prefixed value that is not in the map falls through and returns the list unfiltered, so a typo yields every record rather than none.

    server/main.py:10–15 · server/main.py:26–31 · client/src/components/FilterBar.vue:7–20

  4. 4

    Reports bypasses the API client

    Six views go through api.js; Reports imports axios and hardcodes http://localhost:8001 twice. It is also the only view with no watch() on the shared filters, so it ignores the filter bar entirely. Changing the API origin now means editing two files.

    client/src/views/Reports.vue:128, 156, 162

  5. 5

    CORS is configured in a combination browsers reject

    The middleware sets allow_origins=["*"] together with allow_credentials=True. The Fetch standard forbids a wildcard origin on a credentialed request, so the credentialed path is not actually permitted despite the configuration reading as fully open. Nothing in the app sends credentials today, which is why it has not surfaced.

    server/main.py:48–54

  6. 6

    Smaller notes

    total_backlog_items in the dashboard summary counts the unfiltered list, so it stays constant while every neighbouring figure responds to the filters. useI18n.js reads localStorage at module scope with no guard, which throws during boot in a context where site data is blocked. Currency conversion uses a hardcoded rate of 150.

    server/main.py:200 · client/src/composables/useI18n.js:11 · client/src/utils/currency.js:3

Running it

Two processes, two terminals. uv is a prerequisite and is not listed in the README — install it first if uv is not on your path.

# API — http://localhost:8001, docs at /docs
cd server
uv run python main.py

# Client — http://localhost:3000
cd client
npm install
npm run dev

# Backend tests — 40, from the repo root
cd server
uv run python -m pytest ../tests/backend -q
